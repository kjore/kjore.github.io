开源模型调用

使用 Hugging Face 的 transformers 库可以比较方便地调用开源大语言模型。为了先把调用链路跑通，这里尽量选择一个小模型：

Qwen/Qwen2.5-0.5B-Instruct

这个模型只有 0.5B 参数，适合本地学习和调试。它的能力不能和 7B、14B 甚至更大的模型相比，但胜在下载快、显存占用低、启动成本小。

为什么先选小模型

刚开始学习开源模型调用时，不建议一上来就跑很大的模型，原因是：

  1. 大模型对显存要求更高，环境问题会掩盖调用逻辑本身。
  2. 小模型启动快，适合反复调试 prompt、tokenizer 和采样参数。
  3. 如果只是学习 tokenizer -> model.generate -> decode 这条链路，0.5B 或 1.5B 已经足够。
  4. 小模型可以在很多普通 GPU 甚至 CPU 上跑通，虽然 CPU 会慢一些。

模型权重大致显存可以这样估算：

$$ \text{显存} \approx \text{参数量} \times \text{每个参数占用字节数} $$

以 0.5B 参数为例：

精度 每个参数 权重大致占用
fp32 4 bytes 约 2GB
fp16 / bf16 2 bytes 约 1GB
int8 1 byte 约 0.5GB
int4 0.5 byte 约 0.25GB

实际推理时还会有 KV cache、中间激活和框架开销，所以真实占用会比权重本身更高。

常见问题

下载模型很慢

第一次运行会下载模型权重。如果 Hugging Face 访问慢，可以配置镜像，或者提前手动下载模型到本地。

显存不够

可以按这个顺序处理：

  1. 换更小的模型。
  2. 减小 max_new_tokens。
  3. 尝试量化模型。
  4. 先用 CPU 跑通流程。

输出不符合预期

优先检查：

  1. 是否使用了正确的 chat template。
  2. system prompt 是否太模糊。
  3. max_new_tokens 是否太小。
  4. 采样参数是否过于发散。
